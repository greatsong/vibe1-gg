Non AI

손 코딩 · VPython 3D 물리 시뮬레이션·게임 (GlowScript)

👾 서박이 프로젝트 — 외계인 두더지 게임

결과물 ↗ GitHub ↗

팀원들의 이름을 한 글자씩 딴 자작 외계인 캐릭터 '서박이'가 박스에서 튀어나오면 망치로 잡는, 두더지 게임의 원리를 파이썬으로 파헤친 프로젝트입니다.

깃허브에 남은 4주의 기록

  • 1일차 — 망치 도구와 박스의 형태를 만들다 구멍 뚫는 코드에서 막혔습니다.
  • 2일차 — 구멍을 포기하는 대신 박스로 캐릭터를 가리는 "타협점"을 찾으며, 도움말 대신 조원·선생님과 이야기해 한계를 넘는 법을 배웠습니다.
  • 3일차 — 머리만 움직이던 캐릭터를 compound로 묶어 해결하고, 조건문으로 움직임을 제어했습니다.
  • 4일차 — 캐릭터 6개를 모두 움직이는 대신 2개에 집중하기로 범위를 조정하며 완성도를 지켰습니다.
게임을 만드는 일이 이렇게 고된 일임을 깨달으며 게임 프로그래밍을 업으로 삼는 이들을 리스펙하게 되었고, 문제를 헤쳐 나가며 완성도가 올라갈 때 뿌듯함을 느낍니다. — 수행 기록(log.md) 3일차에서

🎯 물리와 결합한 링 러너

결과물 ↗ GitHub ↗

좋아하는 캐릭터를 compound로 직접 조립하고, 방향키로 조작해 크기가 다른 링들을 통과시키는 3D 게임입니다. 링에 닿으면 Game Over — 충돌 판정까지 손으로 구현했습니다.

깃허브에 남은 기록

  • compound와 keysDown()으로 캐릭터 조립과 x·y·z축 이동을 단계적으로 완성했습니다.
  • 시작하자마자 Game Over가 뜨는 버그를 만나, if 조건문과 and 연산자로 좌표 범위를 좁혀 가며 충돌 판정을 바로잡았습니다.
  • 막히면 교재와 예제로 먼저 스스로 시도하고, 그래도 안 되면 선생님께 질문하는 순서로 해결했습니다.
간단해 보였던 기능도 실제로 구현해 보니 생각보다 많은 조건과 계산이 필요했습니다. 작은 실수 하나로도 결과가 달라져 어려웠지만, 그만큼 논리적으로 조건을 설계하는 힘이 중요함을 느꼈습니다. — 수행 기록(log.md)에서

🦠 감염병 확산 시뮬레이션

결과물 ↗ GitHub ↗

바이러스학에 관심 있는 학생들이 감염병 전파를 눈으로 보이게 만든 시뮬레이션입니다. 하얀 공 사이를 돌아다니는 빨간 공이 닿는 공마다 감염시키고, 키를 누르면 "사회적 거리두기"로 확산 속도가 느려집니다.

깃허브에 남은 8일의 기록

  • 두 원의 중심 거리와 반지름 합을 비교하는 수학으로 감염(충돌) 판정을 구현했습니다.
  • 닿지 않아도 감염되던 버그를 리스트를 새로 설계해 잡고, 복잡했던 거리식을 제곱 연산자로 간결하게 다듬었습니다.
  • 선생님 코드를 그대로 쓰지 않고 "모든 빨간 공이 감염시키게" 직접 고쳐 쓰며 8일차까지 감염자 수 카운터에 도전했습니다.
계획할 때는 쉽게 코딩할 수 있을 줄 알았는데 생각보다 너무 어려웠습니다. 그래도 막연했던 아이디어를 직접 구현하며, 시뮬레이션 하나에 고려할 것이 얼마나 많은지 배웠습니다. — 수행 기록(log.md)과 성찰에서

On AI

바이브 코딩 · 데이터 분석 인공지능 기초 — 공공데이터 분석 웹앱 (Streamlit)

🦠 날씨와 독감 환자 수의 상관관계 분석

결과물 ↗ GitHub ↗
계절별 독감 발생률 분석 — 시즌별 ILI 주간 추이

과정

  • 질병관리청 인플루엔자 의사환자(ILI) 분율 12개 시즌 + 기상청 서울 기온 데이터를 직접 수집해 결합했습니다.
  • 역할을 나눠 데이터 찾기·페이지 구상·AI 활용을 분담하고, 계절별 발생 패턴과 기온의 상관관계를 시각화했습니다.
  • "어떤 프롬프트를 입력해야 원하는 답이 나올까"를 반복해서 고민하며 그래프 구현과 오류 해결에 가장 공을 들였습니다.
직접 페이지 주제·내용·기능을 팀원과 함께 구상하며 소통 능력이 성장했고, AI의 답변을 비판적으로 바라보는 관점도 키웠습니다. — 팀원 성찰에서

💧 지역별로 물맛이 다른가?

결과물 ↗ GitHub ↗
수돗물의 화학 성분이 결정하는 물맛과 보건학적 영향

과정

  • 전국 광역시·지자체 상수도사업본부의 공식 수질 성적표를 전수 조사해 경도·pH·이온 함량 데이터로 정량화했습니다.
  • 일별 데이터만 있는 지역을 제외하는 등 "어떤 데이터를 항목으로 쓸지"를 두고 가장 오래 고민했습니다.
  • 화학 성분과 물맛·보건학적 영향을 잇는 멀티페이지 분석 웹앱으로 완성했습니다.
웹앱을 빠르게 만들어내는 것보다, 어떤 데이터를 선택하고 비교할지 결정하는 과정이 훨씬 중요하다는 것을 배웠습니다. — 팀원 성찰에서

🚇 그래프 이론 기반 지하철 이용 패턴 시각화

결과물 ↗ GitHub ↗
서울 지하철 혼잡도 분석 — 역 245개 · 8개 호선 · 1,671행

과정

  • 서울교통공사 혼잡도 공공데이터로 역·호선·요일·시간대별 이용 패턴을 분석했습니다.
  • 수학의 그래프 이론과 연결해, 혼잡할수록 붉어지는 히트맵과 혼잡역 TOP10 차트를 설계했습니다.
  • 파일 이름 불일치로 특정 호선만 나오던 오류를 추적해 해결하며 데이터 전처리의 중요성을 체감했습니다.
에러가 날 때는 답답했지만, 친구들과 협력하고 서로 보완하며 완성하니 혼자였으면 어려웠을 과정에서 더 좋은 결과물이 나왔습니다. — 팀원 성찰에서
